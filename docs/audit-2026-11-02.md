# Engineering audit — 2026-11-02

## A. Project assessment

Baseline: `152c85a229be37fba9822fc2bbb6ee163b596749`. The initial tree had only
the untracked `schem2net_build_plan.pdf`; it was left alone.

The actual drawing path is `pipeline.run` → `pdf.read` → generator detection →
profile selection → per-page stroke/text recovery, colour or learned-role
classification and grid rescaling → `scene.build` → `symbols.find` and
`fields.annotate` → sheet/unit reconciliation → optional library resolution →
`Netlister.add_page/result`. Altium bookmarks can bypass drawing reconstruction;
all accuracy experiments here disabled that shortcut. Region extraction also
disables it.

PDFium resolves PDF coordinates and forms into millimetres. Scenes distinguish
wires, buses, junctions, graphics, label scopes and sheets. Pins and touching
graphics form symbols; assignment uses drawing order, geometric costs and
learned designator/group models. Library matching checks pin geometry across
orientations and units and can recover stacked pins. Connectivity uses a spatial
index and union-find, with evidence types and consistency checks. The Pydantic
design IR feeds JSON, netlist, schematic, BOM, SPICE, HTML, diff and read-only MCP
queries. The schematic exporter retains geometry and adds labels to carry nets.

The architecture is compact and already uses global assignment and spatial
searches in important places. It does not need a replacement framework. Its
main accuracy gaps remain hidden/unnumbered pins, missed or unnamed components,
pinout ambiguity, and incorrect joins. Confidence weights describe evidence;
they are not calibrated probabilities.

Reviewed areas included the generator profiles, library/hidden-pin handling,
hierarchy and bus resolution, learned feature/training code, exporters and
queries, benchmark splits/scoring/bootstrap, tests, CI, packaging and relevant
history. This is not a proof that every supported format or exporter is correct.

## B. Confirmed problems

| Severity | Location | Reproduction and root cause |
|---|---|---|
| High | `nets.Netlister.result` | The power-conflict check considered only symbol nodes. Local, global and hierarchical textual labels `+3V3` and `+5V` could share a wire without the check firing. Issues also lacked affected pins and net IDs. |
| High | `library.resolve` | Name-only resolution put names such as `GND` and `OUT` in `Pin.number` with provenance `library`. Later name separation did not remove them, so exporters could invent board pad numbers. |
| High | `library._unit_number`, `_fits`, `_stacked` | Numbered units were ignored. A requested unit absent from a library fell back to other units; stacked-pin fallback also ignored the requested unit. |
| High | `pdf.read`, `_read_page`, `_collect`; `pipeline.run/_extract` | The timer started after ingestion. Object checks ran after character extraction, counted retained paths/text instead of visited objects, and silently omitted deeply nested forms. Unknown-generator failure could lose ingestion diagnostics. |
| High, evaluation | `bench.score.align`, `_undo_symmetric_swaps` | Nets underwent symmetric-end swaps and named-placeholder recovery, while issue references did not. Warnings could flag the opposite passive end or disappear from accounting. Three regressions reproduced both directions of the error. |
| High, evaluation | `cli.bench_compare` | Dropping a failing design from the second run still passed: only the intersection was compared. |
| Medium | `kicad_sch._wire_labels` | Both wire grouping and open-end searches scanned all wire pairs. Profiling confirmed quadratic work. |

An actual EasyEDA development case, `cyborg-sch-cyborg`, exposes the textual-label
problem: a 57-pin predicted net carries `+5V`, `GND` and `/IORQ`. Its aligned pins
include 51 from the true `+5V` net and three from `/IORQ`, plus three unscored pins.
The new check explicitly reports the conflict. Its confidence was already 0.6
because of dangling wiring, so the new 0.4 cap does not reduce the silent-error
count or repair its topology.

The unknown-generator concern is also supported by a small development probe:
after recolouring `uwarg-bldc-motor-reversal` black, the connection-count rank
prefers EasyEDA (38, 32.8125% pin accuracy) over Altium (22, 39.0625%). The probe
used each corpus's smallest development PDF and its fold models. This is evidence
against interpreting that ranking as accuracy, not enough evidence for a new
general ranking rule. The zero-score tiny KiCad example would be refused by the
actual fallback, rather than selecting the first tied profile.

## C. Changes implemented

- Inspect textual voltage names across all label scopes. Distinct voltages and
  nonzero voltage/ground conflicts supplement the existing symbol check. Textual
  aliases such as `+5V`/`5v`, `3V3`/`3.3V`, and ordinary signal aliases do not add a
  conflict. Attach the affected pins and stable net ID to power issues. Existing
  power-symbol consistency behaviour and confidence thresholds remain in place.
- Store library-recovered names in `Pin.name`. Respect lettered and numbered
  units (`B`, `.2`, `G2`, `G$2`, `-2`) in both geometric and stacked-pin lookup.
  A regression demonstrates recovery of pads 5 and 7 for a specified second gate;
  an absent unit cannot borrow the first gate or its hidden stack.
- Apply the existing POSIX timer during page loading and ingestion as well as
  analysis. Check the root object count before creating the text page. Count
  visited objects across forms, including images and discarded duplicates; fail
  explicitly on excessive form depth. Close native page/text-page handles as
  they are consumed. Preserve ingestion errors through fallback profile handling.
- Use the existing `GridIndex` for schematic wire grouping and open-end lookup.
  Preserve the original contact predicate and deterministic grouping order.
- Correct issue-reference alignment in the scorer independently of extraction.
  Preserve the old reports and rescore both sets of saved predictions. Keep the
  existing pin/net matching, thresholds, ground truth and split definitions.
- Reject benchmark comparisons with different design sets. No stored baseline
  was replaced or weakened.

recorded, but the models were not independently rebuilt for this audit. No test

## F. Code quality

Changes reuse the existing spatial index, evidence weights, IR issue fields and
matching algorithm. The timer implementation moved from `pipeline.py` to `pdf.py`
so ingestion and analysis share one implementation. The internal page primitive
gained an error field so failed ingestion cannot silently feed partial geometry
into extraction. No dependency, framework, trained artifact, public design schema
or ground-truth change was introduced. No broad style refactor was performed.

## G. Remaining limitations

- Missing pins remain substantial: 14.23% on C, 18.36% on D and 15.16% on E in
  this no-library, out-of-fold development setup. These are not historical test
  percentages. Wrong-net and hidden-pin errors still need source-level diagnosis.
- Error ledgers attribute C's losses primarily to unnamed/missing parts, hidden
  or unnumbered pins and differing pin numbers. E additionally has 5.2% of pins
  classified as renumbered; D has 8.4% on missing parts and 5.7% unnumbered. These
  buckets are diagnostics, not proof of which stage caused every failure.
- Unknown-profile selection can choose a more connected, less accurate reading.
  The small probe does not justify changing the ranking or flagging every net.
- Minimum evidence weights are uncalibrated and include redundant joins. The
  baseline diagnostic AUROCs were about 0.725/A, 0.831/B, 0.783/C, 0.691/D and
  0.749/E under the historical scorer. They need corrected, dedicated calibration
  studies; no probabilistic interpretation or new threshold is claimed here.
- Timers are cooperative Python/POSIX safeguards, not native-process isolation.
  Native calls, initial document opening, bookmark processing, threads, Windows,
  character/path expansion and aggregate document memory still need stronger
  limits. Ingestion and analysis have separate budgets.
- Standalone hidden power pins and project-specific label scope are not generally
  recoverable from drawing geometry. Library fits still use pin geometry, not
  complete body-shape verification; custom/redrawn symbols remain difficult.
- The schematic export still has unresolved ERC/annotation/value issues. Package
  building, MCP transport, Windows and independent test generalisation were not
  validated in this run.
- Learned-asset licensing remains unresolved. Manifests and existing benchmark
  documentation identify source licences including CC BY-SA, GPL and unspecified
  terms; whether derived trees/glyph measurements inherit obligations has not been
  established. No legal conclusion, asset removal or relicensing was attempted.

## H. Next priorities

1. **Recover missing parts and pin identities on C/D/E.** Attribute real failures
   to grouping versus naming versus hidden numbering, then test constrained
   library/body matching and row evidence. High expected benefit, medium effort,
   medium risk of false pinouts. Evaluate with the existing grouped folds.
2. **Repair EasyEDA pin numbering and false joins.** Investigate the renumbered-pin
   concentration and the diagnosed `+5V`/`/IORQ` join at its actual attachment
   edges. High benefit, medium effort/risk; retain only cross-corpus gains.
3. **Calibrate profile selection and review ranking.** Collect out-of-fold
   candidate-profile and edge-level evidence, including contradictory labels,
   redundant joins and no-connect marks. Medium/high benefit, medium/high effort;
   avoid completeness gains bought with silent shorts or excessive review.
4. **Isolate native PDF work in bounded processes.** Enforce deadlines and memory
   limits across opening, ingestion, bookmarks and analysis on supported systems.
   High reliability benefit, medium/high integration cost; exercise crash cleanup
   and multi-page continuation before changing the default execution model.
5. **Complete release reproducibility.** Add recorded model/corpus provenance,
   resolve derived-asset licensing, validate built distributions and optional MCP,
   and expand cross-platform and schematic round-trip checks. High maintenance
   value with little algorithmic risk; some work needs external dependencies or
   licensing decisions.
